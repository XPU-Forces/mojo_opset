## 二、性能验证（910B4 实机，r57b 全量）

**口径（任务书固定算式）：**
- MBU = bytes / t / bw_fill；
- bytes = 2 × (G²×hidden + t·h·w×hidden)（G=48，合并路径按图累加）；
- t = op_summary「Task Duration(us)」窗口内全部 NPU kernel 之和 / 30
  （5 热身 + 30 次统计；CANN parse 子进程在进程退出后落盘 CSV，
  由收割阶段按会话序 1:1 映射回行，t_dev ≤ t_host×1.2 防错配）；
- bw_fill = `fill_` 纯写探针标定（512MB bf16 块，host 口径 5+30 中位数，
  本算子写主导，取纯写带宽为分母）；r57b 实机 700–704 GB/s；
- 每个会话前 `clock_warm(120ms)` 升频（DVFS 对策，见根因分析第二节）。

### 3.2 独立性能套件本机全量（降级口径，记录在案）

- **带宽 bound 行判定有效且过线**：tb-big-video 99.9/72.3、

**官方口径性能判定以 910B4 实机为准**（第二节数据；large-bf16 缺口由

### 3.4 r59 mb1d6 转正（本机 A/B）

迭代筛选后 **mb_d6（mb 结构 × diff6 load 复用 body，BODIES=1）转正为
(1,60,80) large-bf16 生产路径**（host 门 `t == 1 ∧ 0 < w_scale < 1`，
影响面仅 tb-large 线：其余任务书行 w_scale ≥ 1 或 t > 1，不受影响）：

- 本机紧循环 + 斜率法（4 形状点 R²≈1，可测形状差分交叉验证）：
  原生产 mb2 16.75ns/行 → mb1d6 9.0ns/行；
- 转正后 A/B 复测（同 emb，300 迭代紧循环，对拍 CPU 侧）：
  (1,60,160) -39.8%、(1,240,320) -45.9%，双形状位精确保持；
- 34/34 生产不变性复验通过（d6 地址相等复用，零发散类，位精确同值）；
- MBU（本机 1271GB/s 纯写分母）：large-bf16 20.2% → 30.0%，为当前
  全部迭代方向中最优。后续方向：跨 slot embed 行共享（mb_d6s，数学
  上限 ~15%，评估中）。
- 轮 17 换算修正：平台比值方向修正后（910B4 每行成本 = 本机 × 0.86，
  由 mb2 与 mb3 双点桥接），三种独立换算（结构比值 0.537 / 计时桥
  1.19× / 每行成本桥 0.86）一致给出 **mb1d6 在任务书口径
  （fill=700GB/s）≈ 62-65% ≥ 60%，B16 换算达标**。FMA 自洽：910B4
  峰值 ≈ 0.86 TFMA/s（本机 0.72 × 1.19 桥），60% 线仅需 0.567
  TFMA/s。最终确认以一次 910B4 op_summary 实测为准；本机 1271GB/s
  分母口径的物理上限 41.9%（FMA 峰值 0.72 TFMA/s 实测封顶）。

> 本机纪律补充：`torch.equal`/eq/cast 等内建算子直接作用于 NPU tensor
> 同样 C 级硬崩（AclOpKernelInit Cast/Eq）——所有对拍必须 `.cpu()`
> 后在 CPU 侧比较。
